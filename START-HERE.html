This file was opened directly from disk. The prototype will not work this way — browsers block one file from loading another over file://, so every page would render its layout with no data: empty grids, permanent loading states, dead buttons. Start the small server below and it all works.
Want it working right now, with no server? Open standalone.html in this folder — the whole prototype compiled into one self-contained file, so it runs straight from disk. Only screens that take an id in the address (product detail, vendor storefront) need the served copy.
You are running over a server. Everything will work. Pick a starting point below.
Open the start page Open the sitemap Open the landing page

macOS or Linux

Open Terminal, then paste these two lines. Or just double-click start-mac-linux.command in this folder.

cd "path/to/this/folder"
python3 -m http.server 8000

Windows

Double-click start-windows.bat in this folder, or run in Command Prompt:

cd "path\to\this\folder"
python -m http.server 8000

Then

  1. Open http://localhost:8000/
  2. Sign in with any account listed there, or use the dev toolbar in the bottom-right to switch role instantly.

No install, no build step. If python3 is missing, any static server works — for example npx serve . or php -S localhost:8000.

Showing this to someone else? Host it instead and send a link — no server on their machine, and none of this page. See DEPLOY.md.

What is in this folder

51 pages, each a standalone .dc.html file, plus five shared shells and the data layer under assets/js/. Documentation is in docs/ — start with docs/PAGE-INDEX.md for the page map and docs/API-CONTRACT.md for the backend contract.

Data persists in your browser. The dev toolbar can reset it at any time.
